# Snap2Order：生成式数字门店平台的点单底座

更新时间：2026-10-04

面向从单店经营走向品牌化经营、暂时没有独立产品与开发团队的中小餐饮商家，项目计划支持“导入经营资料 → 选择品牌风格与功能 → 预览 → 发布数字门店”。

**当前代码已实现菜单导入、Web 菜单发布、扫码点单和商家接单。品牌风格生成、模块组合和完整门店配置预览仍待开发。** Snap2Order 暂保留为代码项目名称；新版产品名称尚未最终确定。

## 快速运行

需要 Python 3.11 或以上版本。保持项目目录完整，运行以下任一入口：

- macOS：双击 `Start.command`。
- Windows：双击 `Start.bat`。也可以双击 `Startwindows.bat` 启动。
- Linux：运行 `sh start.sh`。
- 通用方式：在项目目录执行 `python3 launcher.py`；Windows 可使用 `python launcher.py`。

启动器会打开浏览器，并自动创建 SQLite 数据库。默认地址为 `http://localhost:8765`；如果端口被占用，启动器会尝试后续端口，以终端显示的地址为准。保持启动窗口打开，按 Ctrl+C 停止。

二维码依赖和 HTTPS 根证书已随项目附带。基本点单流程无需 OCR 或微信密钥：

注册商家 → 手动录入或主动载入演示菜单 → 核对并确认 → 发布菜单 → 顾客下单 → 模拟支付 → 商家处理订单。

演示菜单中的“红油抄于”是供人工纠错使用的示例，不是真实 OCR 结果。

## 不发布到公网，如何让另一台手机扫码下单

本地演示只需让电脑和手机连接同一个允许设备互访的 Wi-Fi，无需公网部署。系统内仍需点击“发布菜单”，顾客才能访问该店内容。

1. 电脑启动服务，确认实际端口，例如 `8765`。
2. 在系统网络设置中查看电脑的局域网 IPv4 地址，例如 `192.168.1.100`。
3. 电脑用 `http://192.168.1.100:8765` 打开商家后台，登录并发布菜单。
4. 在该地址下生成二维码，先确认分享链接使用电脑的局域网 IP。
5. 手机扫码，浏览菜单、加入购物车并提交订单。当前流程需完成模拟支付后，商家才能推进制作状态。
6. 电脑打开接单工作台，查看并处理订单。

局域网 HTTP 演示配置示例：

```dotenv
HOST=0.0.0.0
PORT=8765
PUBLIC_URL=
COOKIE_SECURE=0
```

`PUBLIC_URL` 留空时，网页分享链接基于当前浏览器地址，二维码基于当前请求来源。因此必须使用局域网地址打开后台，不要从 localhost 页面生成供手机使用的二维码。若设置了 `PUBLIC_URL`，分享链接和二维码会优先使用该值；它必须指向本次演示实际可访问的地址。修改配置后重启服务。

常见排查：

- 二维码指向 `localhost` 或 `127.0.0.1`：重新用电脑局域网地址打开后台。
- 端口自动变成 `8766`：手机链接也要使用这个实际端口。
- 手机打不开：先直接输入局域网地址，检查电脑防火墙和 Wi-Fi 的设备隔离设置。
- 配置了 HTTPS 专用 Cookie：本地 HTTP 演示保持 `COOKIE_SECURE=0`。
- 电脑停止服务、休眠或 IP 改变：原链接可能失效，需要恢复服务或更新地址。

HTTP 局域网支持菜单浏览与点单；网页实时摄像头通常要求 HTTPS 或 localhost。商家可先在电脑上传菜单，或使用相册入口，不影响扫码点单演示。

| 路径 | 用途 |
|---|---|
| `/login` | 商家注册与登录 |
| `/merchant/menu` | 菜单导入、编辑、发布和分享 |

## OCR 配置

将 `.env.example` 复制为 `.env`，在 `.env` 填入自己的密钥；已有 `.env` 时直接编辑，不要覆盖现有配置。

```dotenv
OCR_PROVIDER=ocrspace
OCR_API_KEY=填写自己的密钥
OCR_PROVIDER_LABEL=OCR.space
OCR_API_URL=https://api.ocr.space/parse/image
OCR_LANGUAGE=auto
OCR_ENGINE=2
OCR_MAX_IMAGE_BYTES=950000
```

识别链路：浏览器压缩图片 → 服务端 `/api/merchant/ocr` → OCR.space → 菜名和价格配对 → 分类规则推断 → 商家核对。密钥保留在服务端，不发送给浏览器。可参考 [OCR.space 官方接口说明](https://ocr.space/ocrapi)。

当前支持菜单图片，不支持 PDF 菜单导入。复杂多栏、套餐和多规格价格尚未系统评测，需要人工确认。OCR.space 不提供菜品置信度，本项目不会伪造真实识别置信度。识别失败会提示错误并允许手动录入，不会用演示菜单冒充成功。

已有验收记录显示真实 OCR 请求和上传接口成功；这是历史验证结果，不保证任意新密钥、网络或菜单均可识别。保留 `vision` 适配器，如切换服务需同步配置其地址、密钥与模型。

## 菜品图片

每道菜可上传实拍、使用拍照入口、选择推荐插画或不放图片。浏览器将实拍压缩为 JPEG，最长边不超过 1600 像素，文件不超过 2MB。顾客页区分商家实拍和素材示意图。

图片随数据库备份。草稿图片只允许所属商家访问；已发布且上架菜品的图片可供顾客浏览。图片修改需保存草稿或发布，取消图片后需重新发布才能停止公开展示。

## 四步建店与经营配置

商家工作台左侧按“菜单与商品、品牌与店铺资料、功能模块、预览与发布、订单工作台”分区。首页只提供商家入口，顾客仍使用每家门店的独立链接和二维码。

1. 配置品牌与资料：店名、Logo、九套主题、封面、介绍、地址、营业时间和电话。
2. 导入并核对：OCR、手动录入、菜品照片、描述、库存、规格与加料。规格每行一组，例如 `大小份：小份+0,大份+5`。库存留空不限量，0 表示售罄。修改规格与库存后重新确认菜品。
3. 组合功能：在线点单、会员积分、优惠券、幸运转盘、OC 吉祥物各自开关；会员积分可配置注册赠送、每日签到、到店打卡积分，以及"消费每满多少元得多少积分"；配置券的金额与门槛，选择网格或列表布局。OC 模块需先根据文字描述用 AI 生成吉祥物形象（与 AI Logo 共用 AI_LOGO_* 图像服务配置），并依赖会员积分模块。
4. 预览并发布：完整草稿与正式门店共用顾客端渲染。预览支持测试权益交互，不写入正式订单或权益。发布后名称、品牌、页面、模块、菜单统一生效，链接不变。

库存只在下单时按服务端事务扣减；取消、拒单、未支付 30 分钟超时关闭时释放一次。超时由访问接口时检查，订单页面轮询会触发检查。商家可填写缺货拒单原因，搜索/筛选最近 200 笔订单并分页。新订单显示页面提示，点击“启用新单提示”后播放提示音，需保持工作台打开。

会员、优惠券与转盘为基础经营能力：按本设备顾客会话隔离；会员可通过四种方式获得积分——注册赠送（首次加入一次性发放）、每日线上签到、到店扫打卡码打卡、模拟支付消费（每满多少元得多少分，门槛与分值均可由商家配置，签到/打卡/注册赠送的积分数也可配置），签到与打卡每位会员每天各一次。商家发布后可下载"到店打卡码"张贴在店内，顾客扫码打开带打卡入口的顾客页；小程序端微信登录即自动入会，并提供签到与扫码打卡。每日领券一次，转盘每日一次，50% 概率获得本店券。优惠券服务端验证所属门店、顾客、门槛与重复使用。取消/拒单会释放券并回退本单奖励积分。开启 OC 模块后，顾客可在装扮商店用会员积分为全店共享的 OC 吉祥物购买装饰衣物（6 件内置素材，购买后以图层叠加显示在形象上）和动作（4 个内置动作，购买后点击播放 CSS 动画）；装饰与动作的目录和积分价格由系统内置，解锁全店共享。当前没有真实支付、积分兑换、会员等级或复杂营销规则。

## AI Logo

“按经营需求推荐配置”已从商家界面移除。品牌页新增独立的 AI Logo 入口，根据店名、当前品牌风格和图形描述生成图片。配置以下服务端变量后启用：

```dotenv
AI_LOGO_API_KEY=图像生成服务Key
AI_LOGO_API_URL=图像生成接口的完整HTTPS地址
AI_LOGO_MODEL=服务提供的图像模型名称
```

接口使用兼容 Image Generations 的 JSON 请求（model、prompt、n、size），须返回 `data[0].b64_json` 的 PNG/JPEG 图片。若单独的图像 Key 留空，可以使用已配置的 `STORE_AI_API_KEY`；图像 URL 和模型仍需明确设置。返回图片校验后在浏览器压缩并上传到本店 Logo 草稿，发布后公开。生成失败保留原 Logo，仍可手动上传。当前未配置真实图像服务，仅通过模拟响应验证；不会用示意图冒充 AI 生成。

品牌风格可按通用、西餐咖啡、中式餐饮、茶饮甜品筛选；新增简约通用、高端西餐、中式火锅，兼容原六套风格。菜品分类有主食、热菜、凉菜、火锅锅底、肉类、海鲜、蔬菜、小吃、甜品、饮品、套餐和其他候选，同时可自定义。

预览中的加入会员、领测试券、转盘和券抵扣均可体验，仅保存在本次页面内存中，不写正式会员、优惠券、订单。刷新预览重置。预览转盘明确固定演示中奖，正式转盘仍按公布概率。

## 公网部署与 Docker

异地访问需要部署持续运行的 Python 后端，并使用可访问域名。只上传静态网页无法运行登录、OCR 和订单接口。

```dotenv
HOST=0.0.0.0
PORT=8765
PUBLIC_URL=https://你的域名
COOKIE_SECURE=1
```

`PUBLIC_URL` 填写最终访问来源，不带路径或末尾斜杠。`deploy/nginx.conf` 提供 HTTPS 反向代理参考配置。

已提供 Docker 和 Compose 配置，安装 Docker 后可运行：

```sh
docker compose up --build
```

首次构建需要下载镜像。数据存于持久化卷；停止可运行 `docker compose down`，加 `-v` 会删除数据卷。Docker 构建尚未在已有验收中验证。

## 微信小程序

`miniprogram/` 包含顾客端菜单、购物车、下单、模拟支付和订单源码。商家管理仍使用网页。完整导入说明见该目录的 README。

开发者工具需配置真实 AppID 和合法 HTTPS 后端域名。`USE_WECHAT_LOGIN=false` 使用匿名会话；开启微信登录需在服务端设置 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET`。

`/api/auth/wechat` 提供身份交换与绑定；`/api/merchant/minicode` 提供单店小程序码接口，二者需有效平台配置。网页二维码与小程序码是不同入口。当前没有真实微信支付，原生相机、登录、小程序码和真机流程待专项验收。

## 数据与备份

默认数据库：`data/snap2order.sqlite3`，当前结构版本为 5。使用 SQLite、外键、事务和 WAL，保存账号、会话、菜单、订单快照、图片及微信身份映射。历史订单保留下单时的名称和价格；服务端计算金额并校验价格变化，提交编号用于防止重复下单。

运行中请使用在线备份脚本，避免只复制主数据库而遗漏 WAL：

```sh
python3 backup.py /你的备份目录/backup.sqlite3
```

当前工作目录可能已有 `.env` 和业务数据库。向他人转发时，应排除 `.env`、`data/`、缓存、个人账号和业务资料，接收者填写自己的配置。README 不保证当前目录是一份空数据分发包。
